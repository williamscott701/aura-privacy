# aura-privacy

The three public pages for **Aura Migraine Diary**, and nothing else:

| Page | URL | What it is |
|---|---|---|
| `index.html` | <https://williamscott701.github.io/aura-privacy/> | Support and FAQ — the Support URL in App Store Connect |
| `privacy.html` | <https://williamscott701.github.io/aura-privacy/privacy.html> | Privacy policy — `LegalLinks.privacy`, and App Store Connect → App Privacy |
| `terms.html` | <https://williamscott701.github.io/aura-privacy/terms.html> | Terms of use — `LegalLinks.terms`, and App Store Connect → App Information → License Agreement |

App Review opens the privacy and terms links from the paywall and from the Settings
screen, so all three have to resolve without an account.

The repository name is a historical artefact: it was created to serve only the privacy
policy, which was then at the bare base URL. That URL is now the support page, and the
policy has moved to `privacy.html`. The app was repointed in the same change, so nothing
links to the base URL expecting a policy.

## Why this is a separate repository

The app is in a private repository. GitHub Pages needs a public one on a free plan, and
publishing the app repository to serve three pages would also publish its `docs/`: the
keyword strategy, the revenue-model note and the subscription pricing. One extra
repository is cheaper than that.

## Do not edit the HTML here

All three pages are generated by `scripts/make-support-site.py` in the **app** repository
— `williamscott701/aura`, checked out locally at `~/Desktop/Aura/migraine-diary` — which
writes into this directory as its sibling:

```bash
cd ~/Desktop/Aura/migraine-diary
python3 scripts/make-support-site.py
cd ../aura-privacy && git add -A && git commit && git push
```

Editing a page here directly means the next run of the script silently reverts it. The
shared CSS and the page chrome live in the script for the same reason — three
hand-maintained pages is three copies of the same stylesheet.

Change the effective date in the script with any substantive edit.

## What these pages claim, and what has to stay true

The privacy policy states that Aura has no account, no server, no analytics and no
network calls, that it does not use HealthKit at all, and that its App Store privacy
label reads "Data Not Collected". The same claims are on the privacy screen of the app's
introduction, on the privacy card in Settings, on the paywall, and in
`PrivacyInfo.xcprivacy`. Anything that makes a network request falsifies all of them at
once.

The policy is also specific about what the widgets expose — the app-group snapshot holds
counts and dates only, and the Live Activity is the one surface that can put a medication
name on the Lock Screen. If `AuraSnapshot` or `AttackActivityAttributes.ContentState`
gains a field, that section is wrong until it is updated.
